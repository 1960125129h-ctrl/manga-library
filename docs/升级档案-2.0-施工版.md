## 3. 施工项 A：看得清

### 3.1 效果定义（可验收，不靠感觉）

同一页，开与关对比，必须同时满足：

1. 印刷体小字（≤10px）边缘更实，但**白底气泡里的字不出灰边/白晕**
2. 网点纸不龟裂、线条不断裂
3. 彩色页无彩色描边（走"只锐化亮度"档时）
4. 100 页连翻，帧率不低于 50fps

### 3.2 方案：一层实时滤镜，三档参数

原理：CSS `filter` 没有锐化，但 SVG 有。用 `feConvolveMatrix`（卷积）或 `feGaussianBlur + feComposite arithmetic`（unsharp，推荐），挂在页图 `<img>` 上，改属性即实时。

三档：

| 档 | 实现 | 参数 | 适用 |
|---|---|---|---|
| soft | 卷积 | 核 `[0,-0.5,0, -0.5,3,-0.5, 0,-0.5,0]`（和=1） | 高清电子版，只想提一点 |
| medium | 卷积 | 核 `[0,-1,0, -1,5,-1, 0,-1,0]`（和=1） | 默认推荐，≈图3 观感 |
| strong | unsharp | σ=1.1，`k2=1.8 k3=-0.8`（等效锐化量 0.8） | 扫描件、糊图 |

配套：饱和 ×1.08、对比 ×1.05（这也是图3 右半边真正在做的事）。

```js
// 页图滤镜：锐化(url) + 亮度 + 对比，拼成一条 CSS 变量。
// 注意：不动 --r-dim —— 那层遮罩管的是"背景环境暗度"，删了会回归旧观感。
export function applyImgFilter() {
  var parts = [];
  if (S.enhance && S.enhance !== 'off') parts.push('url(#enh-' + S.enhance + ')');
  var b = (typeof S.bright === 'number' && S.bright < 1) ? Math.max(0.2, S.bright) : 1;
  if (b !== 1) parts.push('brightness(' + b + ')');
  var c = (typeof S.contrast === 'number') ? S.contrast : 1;
  if (c !== 1) parts.push('contrast(' + c + ')');
  try {
    document.documentElement.style.setProperty('--r-img-filter', parts.length ? parts.join(' ') : 'none');
  } catch (e) {}
}
```

### 3.4 参数安全区（别越过）

| 源 | σ / 档 | 锐化量 | 备注 |
|---|---|---|---|
| 正常电子版 | soft~medium | 0.3~0.5 | |
| 压缩网图 | medium | 0.5~0.8 | 默认档 |
| 扫描糊图 | strong | 0.8~1.0 | 上限 |
| 网点纸 / 半调 | soft | ≤0.4 | 先降噪，否则越锐越脏 |

红线：锐化量 >1.0 必出光晕；饱和 >1.3 必偏色；对比 >1.2 黑场会死。

### 3.5 验收

- [ ] 三档切换即时生效，翻页不闪白
- [ ] 100 页连翻 ≥50fps（DevTools Performance 抽测一次）
- [ ] 12MP 以上图片自动不挂滤镜，不卡
- [ ] 关掉增强后显示原图（不是残影）
- [ ] 关掉后 `reader-prefs.json` 里 `enhance: "off"`，手机端同步一致
- [ ] 原图文件 hash 与 mtime 不变

### 3.6 坑

1. **显示器缩放**：125%/150% 下滤镜会被系统插值糊掉，看着像没生效 —— 必须在 100% 缩放下验收。
2. **长条模式**：所有页图同时在 DOM 里，N 张图 = N 个离屏缓冲。只给可见页挂滤镜（复用 `render.js:100` 的 IntersectionObserver）。
3. **别挂在容器上**：`filter` 挂到做 `transform: scale` 的 `#canvas` 上会反复重建层，只挂 `img`。
4. **SVG 必须同文档**：`url(#enh-strong)` 只能引当前文档里的 `<filter>`，不能外链。

## 4. 施工项 B：横着看（hscroll / hspread）

### 4.1 两个新模式的语义

| 模式 | 排布 | 用途 |
|---|---|---|
| `hscroll` | 所有页首尾相接的水平长条，滚轮/拖动一路划过去 | 图4 那种长卷式阅读 |

> **`hspread`（"并排"）已废弃删除**：用户指出"双页模式本来就是并排"，这个模式是重复概念。
> 按钮、`core.js` 接线、`MODES` 白名单都已移除；残留的 `hspread` 分支不可达，留着不影响。

### 4.2 关键洞察：改动比想象的小

`#canvas` 本来就是 `display:flex; width:max-content`（CSS:84）。纵向 scroll 是靠 `#stage.mode-scroll #canvas{display:block}`（CSS:85）把它改成块级才实现的纵向堆叠。

**横向 = 保留 flex 的行方向 + 让 #stage 横向滚动。** 不需要重写渲染器，只需要：

1. `render()` 末尾多分派一个分支
2. `scrollToPage` 支持 `scrollLeft`
3. CSS 补几条横向规则
4. 按钮与键位

**② `src/reader/render.js`：把 `renderScroll` 泛化成 `renderStrip(axis)`**

```js
// 组构造：横向 hspread 用两页一组（直接复用 view.js:32 的 spreads()，封面单页逻辑已在里面）
function groupsFor(n) {
  if (S.mode !== 'hspread') { var a = []; for (var i = 0; i < n; i++) a.push([i]); return a; }
  return spreads();
}

export function renderStrip(axis) {
  var p = pages();
  var target = Math.max(0, Math.min(S.pi, Math.max(0, p.length - 1)));
  var gs = groupsFor(p.length);
  var isImg = axis === 'y' ? 'scrollimg' : 'hstripimg';
  for (var g = 0; g < gs.length; g++) {
    var grp = gs[g];
    var w = document.createElement('div');
    w.className = 'pagewrap ' + (axis === 'y' ? 'scwrap' : 'hwrap') + (grp.length > 1 ? ' dual' : '');
    for (var k = 0; k < grp.length; k++) {
      var i = grp[k];
      var im = makeImg(p[i], 'pageimg ' + isImg);
      im.setAttribute('data-i', String(i));
      im.loading = (i <= target) ? 'eager' : 'lazy';   // 目标页之前的必须真加载，否则定位算不准
      w.appendChild(im);
    }
    elCanvas.appendChild(w);
  }
  if (io) { io.disconnect(); setIo(null); }
  var imgs = elStage.querySelectorAll('.' + isImg);
  var th = axis === 'y' ? [0.1, 0.5, 0.9] : [0.4, 0.6, 0.85];
  setIo(new IntersectionObserver(function (es) {
    var best = null;
    for (var k2 = 0; k2 < es.length; k2++) {
      if (es[k2].isIntersecting && (!best || es[k2].intersectionRatio > best.intersectionRatio)) best = es[k2];
    }
    if (!best) return;
    var idx = parseInt(best.target.getAttribute('data-i'), 10);
    if (scrollRestorePage >= 0 && idx !== scrollRestorePage) return;   // 恢复期间不接受远处结果
    S.pi = idx; updateInfo(); syncThumbsActive(); save();
  }, { threshold: th }));
  for (var j = 0; j < imgs.length; j++) io.observe(imgs[j]);
  scrollToPage(target, axis);
}

// 保留旧导出，core 与 nav 都在用
export function renderScroll() { return renderStrip('y'); }
```

### 11.3 滚动手感修正记录（第一版被用户否掉，已重做）

| 版本 | 做法 | 结果 |
|---|---|---|

| 二版 | 按页数跳（`stripJump(1)`）+ 目标页居中吸附 | 键盘对了，**滚轮还是 1 → 3**、甚至 5 → 7 |
| 三版 | 排查出双 handler 冲突 + `min-width` 解析错误 | 滚轮一格 = 一页，键盘 = 一页，落点偏移 0px |

最终行为：

- `→` / `←` / 滚轮一格 / 触控板：**一次一页**（并排模式一次一组）
- 落位：目标页**居中**（不是贴左），偏差 ≤2px
- 到本话头/尾**停住并提示**，不再自动切话（原来会一路连切，用户看到的是"滚着滚着跳到第 3 话"）
- 进度判定改成"中心离视口中心最近的那一张"，不再用 intersectionRatio（一屏两页时两张都是 100%，谁先回调谁赢）


#### 第四版（最终）：横排 = 连续滚动，不是分页器

第一版~三版我都把它做成了"一屏一页 + 按页吸附"的分页器，**方向错了** ——
用户要的是图4 那种"一整条横着划过去"的连续流，跟长条模式对称。修正：

| 改了什么 | 之前 | 现在 |
|---|---|---|
| 排版 | 每组 `min-width:var(--sw)`，一屏一组 | 页首尾相接（`gap: var(--hgap)`），一路连排 |
| 吸附 | `scroll-snap-type` + 按页居中 | 无吸附、无 snap，停在任意位置都合法 |
| 滚轮 | 累积到阈值跳一页 + 450ms 冷却 | `scrollLeft += deltaY × 2.0`，连续、无冷却 |
| 按键 | 跳一页（用 scrollToPage） | 跳到下一页中心，**一次性定位**（不走 scrollToPage） |
| 并排模式 | `hspread` 两页一组 | **删除**（双页模式已覆盖，用户指出是重复概念） |

两个新坑（写下来防复犯）：

1. **`scrollToPage` 是给"打开书时粘住恢复"用的**，它后面 8 秒会反复把视口拽回目标页。
   连续滚动里拿它做翻页，表现就是"滚了一下又被弹回去"。翻页必须自己算一次 `scrollLeft` 就完事。
2. **翻页基线不能取 `S.pi`**，要取"当前居中那一张"。连续滚动下 `S.pi` 比视觉慢半拍，用它做基线会跳过头。

滚轮倍率 2.0 的来由：鼠标一格只有 120px，一页宽 500~800px，1:1 慢得像卡住；
2.0 之后一格 ≈ 240px，两格过一页，跟纵向长条手感接近。


#### 第五版（最终手感）：滚动是连续的，但**停下必须居中**

第四版把吸附全去掉，又走到另一个极端：松手停在半页缝里，视线落在两页中间。
最终方案是"滚动自由、停手归中"：

- **不锁死滚动**：`scrollLeft` 自由加减，可以一路划过去（不是分页器）
- **停手 200ms 后吸附**：把"中心离视口中心最近"的那一页平滑滚到正中
- 触发点在 `elStage` 的 `scroll` 事件上 —— 滚轮、拖滚动条、触控板、方向键全覆盖
- 已经正中（偏差 < 2px）就不动，避免自己吸自己

**滚轮位移按页宽归一**，不再用固定倍率：鼠标一格（120px）= **0.8 页**。
固定倍率（之前 2.0）的坑：页宽 532 时一格只走 240px，不到半页，松手被吸**回原页**，
观感就是"滚了半天没动"。按页宽归一后一格 ≈ 0.8 页，吸附必然前进到下一页。

| 场景 | 实测 |
|---|---|
| 滚轮一格 | 即时位移 398px（≈0.73 页），停下后居中偏差 **1px** |
| 手动把滚动条拖到半页处 | 停手后吸回居中，偏差 **0px** |
| → 键 | 前进一页，落点偏差 **0px** |


#### 第六版（最终形态）：滚轮 = 一次"滚过去"的动画，页间无缝

第五版的"事后吸附"观感很差（用户原话：**拉扯感**）—— 先自由滑一段，200ms 再被拽回中心，
等于同一动作有两个方向。最终改成**一步到位**：

| | 第五版 | 第六版 |
|---|---|---|
| 滚轮 | 自由位移 0.8 页 → 200ms 后吸附 | **一格 = 动画滚一页**（rAF 缓动 0.26/帧，≈300ms 收敛） |
| 方向键 | 瞬间跳到目标位置 | 同样走动画 |
| 页间距 | `gap: var(--hgap, 8px)` | **`gap: 0`**，和长条模式一样页页首尾相接 |
| 吸附 | `scroll` 事件去抖 200ms 后补一次 | **整套删掉**（它就是拉扯感的来源） |

动画滚动目标可被后续调用改写（连续滚轮时不断追加剧程），所以连滚不会抖、也不会返工。

**顺带修掉一个老 bug：切到横排总是落在第 1 页。**
根因是三条叠在一起，缺一条都修不好：

1. `#canvas` 基础样式带 `justify-content:center`，横向内容比容器宽时左半边被裁到滚动区外 → 覆盖成 `flex-start`
2. 图还没解码时 `rect.width = 0`，差值算出来是负数，直接落到 0 → 给每个 wrap 加占位宽 `min-width:calc(var(--sh) * 0.70)`
3. `scrollToPage` 的令牌机制（8 秒 settle）在横向切模式时会被别处的 `cancelScrollRestore` 清掉，之后不再修正 → 横向改用自管的 2 秒短轮询 `alignToPageX`，用户一动就撒手

**翻页基线改回 `S.pi`**：试过"取视觉最居中那张"，动画/布局未定时会算偏一格，
表现是"按一下前进两页"。页码与眼睛一致优先。

> 测试自身的坑：验收脚本为了断言"scrollLeft 可滚动"，直接把 `scrollLeft` 设成 260，
> 然后又去测键盘翻页 —— 基线自然变成第 1 页，看起来像功能坏了。这条断言已经挪到最后执行。

| 场景 | 实测 |
|---|---|
| 滚轮一格 | 位移 540px（正好一页），停下居中偏差 **1px** |
| → 键 | 10 → 11，落点偏差 **0px** |
| 页间距 | **0**（与长条一致，页页相接） |


#### 第七版（现在这版）：滚轮 1:1 连续，停手才对齐

第六版"一格滚轮翻一页"的速度和画面不匹配 —— 长条模式滚多少走多少，横排却一格固定一页，快不起来。
最终把手感对齐长条：

| | 第六版 | 第七版 |
|---|---|---|
| 滚轮位移 | 一格 = 整页（540px） | **1:1**（一格 110~120px，与长条同速） |
| 连滚 | 有 150ms 冷却，快不起来 | **无冷却**，目标累积，4 格连滚实测位移 435px |
| 跟手段 | 每次 smooth 动画 | **瞬时赋值**（跟手），只有最后吸附用 smoooth |
| 停手 | 无（目标就是页中心） | 停手 130ms → 目标吸附到页中心，再 260ms 校验一次 |

**三个关键坑（都踩了）**：

1. **连续 smooth 会互相打断**：每格都 scrollTo({behavior:'smooth'})，前一次动画没跑完就被下一次重置，
   4 格连滚只走了 237px（应为 480）。→ 跟随必须瞬时，只在最后吸附用平滑。
2. **居中基准混用 `clientWidth` 和 `rect.width`**：差 9px 边框 → 每次少补约 5px，永远差一点点。
   统一用 `rect.width`（与按键跳页同一套算法）后偏差 0px。
3. **rAF 在失焦/副屏窗口会被节流**：自定义缓动动画收不了尾，残留 5~6px。→ 换原生 `scrollTo smooth`，
   由合成器驱动，不受 rAF 节流影响。

| 场景 | 实测 |
|---|---|
| 滚轮一格 | 110px（1:1） |
| 连滚 4 格 | 435px（能快速划过） |
| 停手后居中 | **0px** |
| → 键 | 14 → 15，落点 **0px** |


#### 第八版（当前）：回滚到"一格一页"，冷却 150ms → 50ms

第七版（1:1 连续 + 停手吸附）实测**拉扯感又回来了** —— 吸附是第二段运动，
方向和滚轮不一致时最难受。已回滚到第六版的行为，只把冷却从 150ms 调到 **50ms**：

| | 第七版（已废） | 第八版（当前） |
|---|---|---|
| 滚轮一格 | 1:1 走 110px，停手再吸附 | **直接滚一页**（实测 546px），一次运动到位 |
| 冷却 | 无 | **50ms**（连滚更跟手，实测 4 格推进 1632px） |
| 二次运动 | 有（吸附） | **没有** |

保留的修复（与滚轮手感无关，都是真 bug）：页间距 0、切模式落回当前页、居中基准用 `rect.width`、
`justify-content:flex-start`、占位宽、翻页基线用 `S.pi`。

> 结论：横排的滚轮就该是"一格一页 + 一次动画"。连续滚动 + 事后对齐试了两轮，
> 用户实测都有拉扯感 —— 这条路不要再走。

| 场景 | 实测 |
|---|---|
| 滚轮一格 | 546px（正好一页），落点 0px |
| 连滚 4 格 | 1632px（约 3 页，能快速连翻） |
| → 键 | 2 → 3，落点 0px |


#### 第九版：滚轮能一路滚进下一话 + 预加载下一话

之前滚到本话末尾只是停住提示（当初是为了避免"连切到第 3 话"的投诉）。现在改成**滚到底就进下一话**，
并且提前把下一话头几页解码好：

| 行为 | 实现 |
|---|---|
| 滚到末尾继续滚 | `stripJump(+)` 返回 false → `nextChapter()` |
| 滚到开头继续滚 | `stripJump(-)` 返回 false → `prevChapter(true)`（落在上一话最后一页） |
| 方向键 | 同上（与滚轮一致，不再只弹提示） |

#### 第十版：章节中割（一话末尾直接接下一话，中间一条章节号竖条）

需求原话："在第一话的末尾跟上第二话……中间插上一个他们的中间的章节号，作为一个中割"。

实现：

- `renderStrip('x')` 渲染完当前话后，调 `window.__stripAppendNext`（nav 注册的钩子，沿用项目里 `window.__qclearSync` 那套做法，避免 render ↔ nav 循环 import）
- 追加一个 `.chbreak` 竖条（86px 宽，竖排章节名 + ▸ 箭头）
- 再追加**下一话前 6 页**（`.hstripimg.extra`），前 3 页 eager —— 顺便就当预加载
- 进度观察器排除 extra：`querySelectorAll(".hstripimg:not(.extra)")`
- 滚动停下 120ms 后检查中割中心是否越过视口中线 → 越过就 `nextChapter()`（900ms 锁防连切）
- 最后一话不加中割（`chStep(1) < 0` 直接返回）

效果（见 `_visual-check/2.0/05-chapter-break.png`）：左边是上一话最后一页，中间竖排"第 04 話"，
右边直接是下一话第一页 —— 一路滚过去就换了话，不需要停在末尾再点一次。

实测：`46 第3卷特典 -> 67 第03卷番外`（滚过中割自动换话）；中割章节名"第 04 話"，预接 6 页。


#### 第十一版：中割越过时不重建画布（消除闪跳）

第十版越过中割是调 `nextChapter()` → `render()` 重建整条画布，用户实测"会闪一下、跳到下一话开头"。
改成**就地转正**（`promoteNextChapter()`，在 `src/reader/render.js`）：

1. 记录本话所有页的总宽度 `removedW`
2. `S.ci = 下一话`，把已经渲染好的"下一话前 6 页"去掉 `.extra` 标记、补 `data-i`
3. **删掉本话的页和中割**，`elStage.scrollLeft -= removedW` —— 视觉位置纹丝不动
4. 观察器重挂到转正后的页上（`applyPickX` 已提到模块级，两处共用）
5. 末尾再追加"新的中割 + 再下一话 6 页"，所以可以一直滚下去

**全程没有任何元素被重建**，所以不存在白闪和位置跳。转正后 `S.pi` 取"当前视口中心那一页"，
不是 0 —— 否则画面会跳回下一话第 1 页。

兜底：`pendingNext` 为空（用户手动滚过头等）时回退到 `nextChapter()` 重建路径。

实测：`第02話 -> 46 第3卷特典 -> 67 第03卷番外`（连续滚过两个中割，两话都正常转正）。


#### 第十二版：滚轮也走"推进中割"的路（拖滚动条早就顺，滚轮不顺）

用户实测：**拖滚动条能自然进入下一话，滚轮却是闪跳**。原因是两条路不一样：

| 入口 | 路径 | 结果 |
|---|---|---|
| 拖滚动条 / 触控板 | `scroll` → `checkChBreak` → `promoteNextChapter` | 就地转正，顺滑 |
| 滚轮 / 方向键 | `stripJump` 到头 → **`nextChapter(){BT} 重建画布** | 闪跳 |

修法：到头时**不要** `nextChapter()`，而是继续把画面往前推 0.55 屏，
让"中割 + 下一话开头"自然滑进视口，越过中线后仍由 `checkChBreak` 就地转正。
（实在没有中割时才回退到重建，比如手动拖过头。）

同一条路现在三个入口都走：滚轮 / 方向键 / 拖动。

**验证方式换成"DOM 身份"而不是肉眼**：滚过中割前把某个预接页元素存进 `window.__probeEl`，
转正后检查这个元素是否**仍然在文档里且已摘掉 `extra` 类**：

```
PASS  转正复用预渲染页（没重建画布）   预接页元素 仍在且已转正
PASS  滚过中割自动换话                67 第03卷番外 -> 第03話
```

元素没被销毁 = 预加载的图真的被用上了，不是重建后重新加载。


#### 第十三版：卡死的原因 + 转正时机推到"下一话第 3 页之后"

**卡死根因（严重 bug，已修）**：
`checkChBreak` 挂在 `scroll` 上、120ms 去抖，但**没有"这条中割已处理过"的判断**。
中割一旦越过中线，每次滚动检查都会调一次 `promoteNextChapter`，
而每调一次又会追加"6 页 + 一条新中割" —— DOM 无限增长，浏览器直接卡死。
（用户报"现在卡住了"就是这个。）

修复三条：

1. `lastHandledMarker`：同一个中割元素只处理一次，转正后它已被移除，新中割是另一个元素
2. 转正条件从"中割过视口中线"改成 **"视口已经滚到下一话第 3 页之后"**（`centerIdx >= 2`）
   —— 前两页留作缓冲：用户能看清"这是下一话开头"，也给解码留出静止时间
3. 转正后锁 1500ms

副作用（符合预期）：滚到本话末尾后，**要连滚几格**才真正换话（一格只推进 0.55 屏）；
这不是卡住，是在把中割和下一话的前几页一页页划过去。

**另一个环境坑**：验收脚本一度用独立 `--user-data-dir` 跑（为了不和用户正在用的实例抢单实例锁），
结果首启会弹"使用引导"——它在 `#modal` 里，而 core 的 keydown 里有一句
`if (elModal.classList.contains("on")) return;`，于是**所有按键和滚轮全被吃掉**，
表现为"翻页没反应"。要么跑之前先关掉引导，要么用正常 profile 跑。

实测：`第03話 -> 69 第4卷番外`（滚过中割）、`69 第4卷番外 -> 第04話`（连滚 6 格到末尾）。


#### 第十四版：落点固定在「下一话第 4 页」

用户要求：转正落在第 4 页（不是"看到第 3 页又被送回第 1 页"），预接 8 页，保留上一话最后 3 页。

**改法**

| 环节 | 之前 | 现在 |
|---|---|---|
| 触发 | 中割过中线 | 落点章节的**第 4 页**跑到视口中线 |
| 落点 | `S.pi = centerIdx`（猜，会跳回 1） | **`S.pi = 3`**，并把第 4 页精确居中（偏差 <1px） |
| 位置补偿 | `scrollLeft -= removedW`（累加宽度，不准） | 用**锚点元素删除前后的屏幕位移**补偿，再对第 4 页精修 |
| 预接 | 每话 6 页 | **8 页**（第 4 页前后都有内容） |
| 上一话 | 全删 | **保留最后 3 页**（可往回滚对照中割） |
| 短章节 | 直接跳过 | **继续往后接一话**，直到找到有第 4 页的当落点（最多接 3 话） |

**过程中揪出两个硬 bug**（都是上一版留下的）：

1. `pendingNext` 的赋值条件还停在旧格式 `typeof nx.idx === "number"`，而 nav 现在返回 `{chain}` ——
   条件永远为 false，**转正逻辑根本没被触发过**。这也解释了"看到第 3 页就闪回第 1 页"的一部分现象。
2. 转正只把预接的 8 页转正，**长章节后面几十页是空的**（31 页的话滚到第 9 页就断）。
   补了 `fillRestPages`：转正后按 `target.pages.length` 把剩余页追加进来。

**trace 实测**（真实滚轮，一格一格）：

```

第5格: 67 第03卷番外 4/31  ← 滚过中割，落在第 4 页
第6格: 67 第03卷番外 5/31  （页码连续，formal=31 页已补齐）
```

> 验收脚本里还有 2~3 条**时序敏感**的断言（键盘焦点是否在输入框、一次滚多少格才够跨过中割）会偶发失败；
> 关键项（中割存在 / 滚到末尾进下一话 / 转正复用预渲染页不重建）稳定通过。

#### 第十六版：转正时机提前到「第 4 页刚到」，不再翻到第 5 页才被拽回

用户反馈："翻到第 5 页的时候，它会跳到第 4 页，而不是在第 4 页的时候跳到第 4 页" —— 典型的中断感。

原因两条，都在"判定太慢"上：

1. 转正判定挂在 `scroll` 上、去抖 120ms。滚轮一格一页的动画只要 300ms，
   等去抖结束，视口早就跨到第 5 页了
2. 转正时还**强制把第 4 页拉到正中**，于是画面从第 5 页被拽回第 4 页

处置：

| 改动 | 从 | 到 |
|---|---|---|
| 判定时机 | 只在 scroll 去抖后 | **每次翻页动作完成 90ms 后立刻判一次**；scroll 去抖 120ms → 50ms |
| 阈值 | 第 4 页中心越过中线 | 第 4 页中心进入中线右侧 **120px** 就触发 |
| 转正后定位 | 强制把第 4 页拉到正中 | **不强制**，只做锚点补偿；偏差超过 0.6 页才纠正 |

**trace（真实滚轮）**

```
7格: page=8 total=/8  sl=7142 p4off=-5202     ← 本话末页
8格: page=4 total=/12 sl=1328 p4off=20    ★转正   ← 第 4 页距中心 20px，画面基本没动
```

> 另外顺手给 `stripJump` 加了 450ms 的页码冻结：往回翻时动画没跑完，
> IO 会按"最居中"把 `S.pi` 抢回原页，表现就是"3→2 了但页码还显示 3"（用户说的 3221）。
> 用户反馈这条已经好了，冻结保留着当保险。


#### 第十七版：中割区也逐页对齐（已知：连滚到末端偶发不转正）

用户指出：中割条从 86px 加宽到 150px 后，**预接的那几页停在半页上、没有居中** ——
因为那时滚轮走的是"盲推 0.55 屏"，不是"对齐到页中心"。

改法：中割区（`.hstripimg.extra`）也走逐页对齐 —— `nextExtraCenterX()` 找"中心在当前视口中心右侧最近的预接页"，
滚轮/方向键都调到那一页的中心。体验和正式页一致，滚到第 4 页时正好居中，然后转正。

末端兜底：预接页走到最后一个还没转正 → 先试转正，不行就直接 `nextChapter()`，不会卡死在最右端。

**遗留问题（未解决，需下一轮）**

验收里"连滚 22 格跨话"这一条会失败：极端连续滚动时，转正有时不触发，最终走了重建路径

滚到中割区后 `S.pi` 停在末页不动，而转向"逐页对齐预接页"的分支需要更精确的状态同步。


#### 第十八版：按日志定位到的三处「乱」并修掉

用户录了一段操作日志（`_logs/hscroll-*.jsonl`，41 次滚轮 / 179 个采样 / 5 次章节变化），
日志把问题摊开后是三个独立的点：

| 日志现象 | 根因 | 修法 |
|---|---|---|

#### 第十九版：终于抓到「突然往回滚」的真凶 —— 重复的 `data-i`

用户第二段日志（82 次滚轮 / 330 采样 / 5 次转正）里，异常长这样：

```
21:30:42.525  page=6  sl=4438  cI=4  off=0      ← 正常：第 6 页居中
21:30:42.643  scroll  sl=4307                   ← 一次滚轮之后，开始往回滚
21:30:42.843  scroll  sl=2258
21:30:43.045  scroll  sl=833
21:30:43.548  scroll  sl=24                     ← 一路扎回开头 4700px
```

采样里还能看到 `cI` 从 4 跳到 1 又跳到 7、`off` 忽大忽小 —— 这说明**视口中心对应的图在乱换**。

**根因**：转正时"保留上一话最后 3 页"（用户要的 3B），这几页还带着**上一话的 `data-i`**（比如 5/6/7），
而新话的页也从 0 开始编号 → **同一个 `data-i` 在 DOM 里出现两次**。
`stripJump` 定位下一页用的是 `querySelector('.hstripimg[data-i="5"]')`，它返回**文档顺序里第一个**——
也就是左边那几页残留的上一话页。算出来的位移是巨大的负数，画面就一头扎回前面去了。

**修法**：保留的页一律 `removeAttribute("data-i")` 并打上 `prevch` 类，不再参与页码定位。

**trace 实测（修复后，从末页一路滚）**

```

5: 第04話 page=4/10  cI=3  off=0    ★转正（scrollLeft 数字变小是删页重算，画面没动）
6: page=5/10  cI=4  off=1
7: page=6/10  cI=5  off=0
8: page=7/10  cI=6  off=1
9: page=8/10  cI=7  off=0
10: page=9/10  cI=8  off=2
```

`cI` 与 `page` 一一对应、`off` 稳定在个位数、不再出现回滚。
（转正那一格 `scrollLeft` 数字会骤降，那是删掉前面几十页后的重算，锚点补偿保证画面不动，`off=0` 即为证。）


#### 第二十版：转正后右侧缩略图不跟着换话

用户反馈：横排转正之后，右侧缩略图还停在上一次渲染的那一话（甚至更早的几话）。

原因很直接：缩略图列表只在 `render()` 里通过 `applyThumbs()` 重建，
而"就地转正"（`promoteNextChapter`）**刻意不走 render()**（为的就是不重建画布、不白闪），
于是缩略图从来没被通知过换了话。`syncThumbsActive()` 只能改高亮，改不了列表内容。

修法：promote 成功后在末尾补一次 `applyThumbs()`（它会按 `S.ci + 页数 + 倒序标志` 生成新的 sig，
sig 变了就整表重建）。代价只是换话那一下重建几十个缩略图，不影响滚动。

**验收**：`缩略图 sig|数量 = 6:10:0|10` —— sig 里的章节号 6 与当前话一致、10 个缩略图。


#### 第二十一版：整页模式下的缩放基准修正

用户报：单页 + **整页**模式下右键滚轮放大，图片不是从"当前显示大小（约 45%）"放大，
而是直接跳到原图大小。适高模式正常。

**原因**：整页模式的 CSS 是 `width:100%; height:100%; object-fit:contain` ——
元素框被撑满容器，`getBoundingClientRect().width` 量到的是**容器宽**（887px），
而图片靠 contain 只显示 554px。`applyZoom` 把这个 887 当成"100% 基准宽"，
一放大就按 887 算，视觉上直接跳到原图大小。

**修法**（`src/reader/zoom.js:53` 附近）：测量基准宽时判断"框是否被容器化"——
框的宽高比与图片自然宽高比差 >2% 就认定是，然后用 contain 公式还原真实显示宽：

```
真实显示宽 = naturalWidth × min(框宽 / naturalWidth, 框高 / naturalHeight)
```

其余缩放逻辑（右键拖动、以光标为锚点、退出复位、双页/长条）一律不动。

**验收（新增 `verify-zoom.mjs`）**

```

整页模式 之后: shown=609              ← 554 → 609 = 110%
重置后:        554                     ← 回到原样
适高模式:      554 → 609 = 110%       ← 回归没坏
```

## 12. 章节排序修复（2026-11-13）

### 12.1 问题

「脑洞学生会」的章节目录是乱的：

```
21 01卷附录 → 第01話 → 26 第2卷特典 → 第02話 → 46 第3卷特典 → 67 第03卷番外 → 第03話 → …
```

### 12.2 根因

`_scripts/build-library.mjs` 的 `chapterNo()` **先抓话号**，而这些特典名字里同时带目录序号和话号：

| 目录名 | 目录序号 | 名字里的话号 | 旧规则取到 |
|---|---|---|---|
| `21 01卷附录` | 21 | 01（卷） | **1** |
| `26 第2卷特典` | 26 | 2（卷） | **2** |
| `72 60话番外` | 72 | 60 | **60** |

撞上主线「第01話」「第02話」后同号，退化按字符串排 → 数字开头的全挤到前面。

### 12.3 规则（最终：混合）

1. **小数话号优先**（`13 第11.5话` → 11.5）：必须插在 11 和 12 之间
2. 否则**开头的目录序号**（`21 01卷附录` → 21）
3. 否则整数话号
4. 同号时按名称自然序（`natCmp`）

### 12.4 全库影响面（实测 1575 本）

| 类别 | 本数 | 结论 |
|---|---|---|
| 三套规则结果完全相同 | 1559 | 不受影响 |
| 新规则**修好** | 12 | 特典/番外回到目录位置（脑洞学生会、蔚蓝档案、超超超喜欢你 288 章…） |
| 纯"序号优先"会**弄坏** | 4 | 小数话号书（总之就是非常想做 / 魔女与佣兵 / 梅子和小桃 / Scavengers）—— 混合规则下保持正确 |

最终按混合规则重排了 **11 本**数据（只有这 11 本与规则不一致），复核后**全库 0 本不一致** ——
即以后点「更新书库」重扫，顺序也不会再变。
