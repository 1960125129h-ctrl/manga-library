# 站点适配维护指南

改一个站点的取数规则、或加一个新站点时，照这个流程走。核心就一句：
**适配器是随安装包分发的脚本，改完必须发一个新版本，用户的「书库目录」才会跟着更新。**

---

## 一、适配器在哪、要做什么

```
_scripts/sites/
  index.mjs       注册表：export const ADAPTERS = [...] 和 pick(url)
  contract.mjs    契约校验（返回值字段的硬性要求）
  fetch-book.mjs  通用下载器：调适配器 + 存图 + 入库
  <站点>.mjs      一个站点一个文件，实现下面这些导出
```

一个适配器要导出：

| 导出 | 作用 | 必须 |
|---|---|---|
| `id` | 站点标识（写进 library.json 的 `source.site`） | ✅ |
| `match(url)` | 这个链接归不归我管 | ✅ |
| `resolve(url)` | 解析成 `{ title, author, desc, cover, chapters? }` | ✅ |
| `chapters(book, opts)` | 返回章节数组 `{ id, title, url, index }` | ✅ |
| `images(ch)` 或 `download(ch, dir)` | 拿到图片地址列表 / 直接下到目录 | ✅（二选一，看站点类型） |
| `tagGalleries(keyword, page)` | 标签/作者页批量枚举（前端「跨站搜索」用） | 可选 |
| `search(keyword)` | 站内搜索 | 可选 |

**契约是硬的**：`gid` / `url` / 图片地址 这类"找不到就下不到"的字段缺一个，`contract.mjs` 直接抛错并指出是第几项缺什么；`title` / `thumb` 缺了只补默认值。别绕过它——抖音作者页那次就是因为 `tagGalleries` 少给 `gid`，界面表现为"勾了没反应"、零报错。

## 二、改完怎么自测

```powershell
# 1) 契约层（秒级，改完先跑这个）
node _scripts\jm\verify-contract.mjs

# 2) 真下两页（走完整链路：解析 → 取图 → 存盘 → 入库 → 重建）
node _scripts\jm\verify-download.mjs

# 3) 全量回归（11 个工具 / 167 项，改完最好跑一遍）
node _scripts\jm\verify-all.mjs
```

只用接口、不碰浏览器的站点（再漫画 / Komiic / pixiv / nhentai / EH / 微博）上面三条就够。
需要调试浏览器登录态的（X / 抖音 / 禁漫），先在应用里打开浏览器并登录，再跑 `verify-download`。

站点临时改版时最快的验证方式：拿一条真实链接直接跑下载器，看控制台报什么：

```powershell
node _scripts\sites\fetch-book.mjs --url "<目录页链接>" --dir "临时书名" --from 1 --to 2
```

## 三、加一个新站点（五步）

1. 复制一个最像的现有适配器当模板：`_scripts/sites/zaimanhua.mjs`（纯 HTTP API）或 `xmanhua.mjs`（HTML 解析）
2. 改 `id` / `match` / 各函数实现
3. **在 `_scripts/sites/index.mjs` 注册**：`import * as 新站点 from './新站点.mjs';` 并加进 `ADAPTERS`（漏了这步，下载器永远找不到它）
4. 前端站点清单也加一条：`src/shelf/site-data.js`（「跨站搜索」和站点说明用）
5. 跑第二节的三条命令

## 四、发布（关键：用户怎么拿到新适配）

适配器是**随包分发的脚本**，不是远程热更新。流程：

```powershell
# 1) 改 _app/package.json 的 version（1.0.2 -> 1.0.3）
# 2) 打包
cd _app; .\node_modules\.bin\electron-builder.cmd --win
# 3) 发 Release（tag v1.0.3），上传 _dist\书库-1.0.3-setup.exe
```

用户端：应用启动时会静默检查更新 → 弹窗提示 → 装完新版本后，**首次启动会把新的 `src/` 和 `_scripts/` 同步进他的书库目录**。

同步规则（`_app/main.js` 里的 `syncLibraryResources`）：

- 用「资源签名」判断要不要覆盖：签名包含 **版本号 + 关键文件 + `_scripts/sites/` 与 `_scripts/jm/` 下每个脚本的文件名和大小**
  → 所以**只要改了任一适配器，签名就变，用户升级后一定会拿到新脚本**
- 覆盖 `src/`、`_scripts/`（跳过 `tools/` 那 300MB）`icons/`、`manifest.webmanifest`、`service-worker.js`
- **不动**用户数据：`漫画/`、`library.json`、`.progress.json`、`_thumbs/`、`_scripts/sites/cookies/`、`_scripts/sites/download-prefs.json`
- 书库目录里会写一个 `.pkg-version` 记签名，签名一致就不再动

如果只是**自己临时修**、不想发版：直接改书库目录里的 `_scripts/sites/<站点>.mjs`（开发时就是仓库里这份），改完重开应用即可生效；但下次版本升级会被覆盖。

## 五、常见坑

| 现象 | 原因 / 处置 |
|---|---|
| 改了适配器，用户那边没变 | 没发新版本；或只改了书库目录、又升级被覆盖。看 `.pkg-version` 与设置里的版本号 |
| 下载报"适配器返回值不符合契约" | 按报错里的「第几项缺什么」补字段，别用 try/catch 吞掉 |
| 界面"勾了没反应" | 大概率 `tagGalleries` 少了 `gid`/`url` |
| 走代理的站 403/超时 | 设置里看代理端口（默认 7890），或该站需要先登录抓 cookie |
| 站点要过 Cloudflare | 纯 HTTP 适配器不行，改用浏览器链路（参考 `jm-auto.mjs` 的 `--img` 回退） |
