# 内容分级开关 · 设计方案

> 状态：**未实施**，2026-11-14 讨论记录。
> 目标：降低分发过程中的风险暴露面，同时保留完整功能。

---

## 1. 背景

应用为 Windows 桌面端，通过 GitHub Releases 分发。担心的不是应用商店审核，而是：

1. 仓库或发布页被举报下架；
2. 界面截图被传播后引起注意；
3. 代码仓库被检索到敏感内容。

因此需要的不是"审核过审"，而是**减少可被举报的抓手**。

## 2. 当前暴露面（实测盘点）

| 层级 | 位置 | 现状 | 风险 |
|---|---|---|---|
| 站点清单 | `src/shelf/site-data.js` | 含若干明文域名与站名 | **高**：代码搜索可直接命中 |
| 界面入口 | 「站点总览」逐个列出站名 | 打开即见 | **高**：用户截图天然带入 |
| 适配器代码 | `_scripts/sites/` 下两个特定适配器 | 域名写在文件内 | 中 |
| 目录名与文档 | `_scripts/jm/` 及其 README | 目录名有暗示性，文档写有站点维护方法 | 中 |
| 发布说明 | Release 正文 | 目前只写"支持站点"，未列站名 | 低 |
| 打包产物 | 空 `library.json` 模板 | 不含个人内容是干净的 | 低 |

**结论：主要抓手集中在"文字"和"截图"，而非运行逻辑。**

## 3. 方案对比

| 方案 | 做法 | 包内是否残留 | 评价 |
|---|---|---|---|
| **A. 开关隐藏** | 代码保留，配置默认关闭 | 有 | 静态扫描仍可命中，收益有限 |
| **B. 注释入口** | 界面不显示，模块照常打包 | 有 | 解包可见，收益有限 |
| **C. 构建时剥离** | 打包脚本按开关决定是否带上特定适配器 | 无 | 最彻底，但需维护两条构建线 |
| **D. 连点版本号** | 默认关闭入口，连点若干次解锁 | 有 | 解决观感，不解决代码证据 |

**判断**：A / B / D 都属于"降低观感"，只有 C 是"降低证据"。当前阶段优先 D，视情况叠加 C。

## 4. 连点解锁 · 完整设计

### 4.1 交互

- 设置面板中的版本号文字（`版本 1.1.x`）监听点击；
- 3 秒内连续点击 7 次触发；
- 触发后弹出确认框，确认则写入 `config.json` 的 `adultMode: true`；
- 关闭方式：同一位置再次连点 7 次，或解锁后出现的复选项。

### 4.2 状态存放

放 `config.json`（主进程管理），**不放 localStorage**：

- 清缓存不会重置；
- 渲染层无法篡改；
- 主进程启动时读一次，决定加载哪些适配器。

### 4.3 过滤必须落三层

只做界面层是不够的 —— 用户直接粘贴链接仍然可以下载，等于没关。

| 层 | 位置 | 关闭时的行为 |
|---|---|---|
| 适配器注册 | `_scripts/sites/index.mjs` / 下载器加载逻辑 | 跳过特定适配器，贴链接会提示"不支持的站点" |
| 站点清单 | `src/shelf/site-data.js` 渲染处 | 过滤掉对应分组，不渲染 DOM |
| 界面入口 | 下载面板页签 | 隐藏对应页签 |

### 4.4 已下载内容

**不隐藏**。

理由：
- 属于用户自有数据，隐藏会让用户误以为丢书；
- 只关"获取入口"，不关"浏览入口"。

## 5. 可选加强：站点清单外置

把 `site-data.js` 的站点数据移到热更新下发的远端数据中，使**主仓库代码内不含任何站名字符串**。

| 项 | 说明 |
|---|---|
| 收益 | GitHub 代码搜索无法命中 |
| 成本 | 首次启动需联网拉取一次；离线用户看不到列表 |
| 与连点的关系 | 连点挡观感，外置挡代码搜索，二者互补 |

## 6. 实施顺序（建议）

1. **连点解锁 + 三层过滤**（约半天）
2. **站点清单外置**（约半天）
3. （按需）**构建时剥离 + 双构建线**（约一天）

## 7. 成本估算

| 部分 | 工作量 |
|---|---|
| 版本号连点监听与计数器 | 0.5 小时 |
| 主进程读配置 + 适配器过滤 | 1 小时 |
| 站点清单与界面过滤 | 0.5 小时 |
| 关闭入口（锁回去） | 0.5 小时 |
| 三处入口验证（贴链接 / 列表 / 页签） | 1 小时 |

## 8. 不做的事（看似有效，实际无用）

| 做法 | 原因 |
|---|---|
| 字符串加密 / Base64 | 静态扫描工具会尝试解码，运行时必然明文 |
| 仅在代码中隐藏、界面照旧 | 界面截图才是主要证据来源 |
| 依赖免责声明显著降责 | 平台判定依据是内容本身 |
| 关键词拆分拼接 | 相邻字符串仍可命中，且明显是刻意规避 |

## 9. 待决事项

1. 只做连点，还是连点 + 站点清单外置？
2. 已下载内容是否隐藏（当前倾向：不隐藏）；
3. 解锁入口位置：设置页版本号 / 书架首页版本号；
4. 是否需要额外口令（连点后输入字符串才生效，进一步降低被误触发的概率）。
